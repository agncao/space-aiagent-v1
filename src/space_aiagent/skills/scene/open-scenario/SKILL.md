# 打开场景

严格按以下顺序执行。不要跳过查询，不要根据记忆或当前场景状态猜测目标场景。

## 1. 确定查询方式

### 用户未指定名称

例如「打开场景」「切换场景」「进入场景」。仅在这种情况下查询全部场景：

```text
query_scenario()
```

### 用户明确指定完整名称

以下表达已经明确划定真实场景名，优先级最高：

- 使用成对引号包围名称，包括 `"..."`、`“...”`、`'...'`、`‘...’`、`「...」`。
- 使用「叫」「叫做」「名为」「名称为」「名称是」等明确命名词。

只提取被明确划定的名称，调用一次 `query_scenario`。不要追加或删除「场景」，结果为空或
返回 `SCENE_NOT_FOUND` 时也不要扩大查询。

```text
# 「打开叫航天飞行任务的场景」：“的场景”是语法成分，不属于名称
query_scenario(scene_name="航天飞行任务")

# 「打开“航天飞行任务”场景」：引号内容是完整名称
query_scenario(scene_name="航天飞行任务")

# 「打开“航天飞行任务场景”」：引号内的“场景”属于名称
query_scenario(scene_name="航天飞行任务场景")
```

如果引号规则和命名词规则同时出现，以引号中的内容为完整名称。

### 用户未明确划定完整名称

先去掉「打开」「切换到」「进入」等操作词以及名称两端的分隔空格，保留用户表达中属于名称的
「场景」二字。不要一开始就把「场景」当作操作词删除。

| 用户表达 | 第一次查询名 | 空结果后的第二次查询名 |
|----------|--------------|--------------------------|
| 打开 / 切换到 / 进入 `xxx场景` | `xxx场景` | `xxx` |
| 打开 / 切换到 / 进入 `场景xxx` | `场景xxx` | `xxx` |
| 打开 / 切换到 / 进入 `xxx`（名称边界不含「场景」） | `xxx` | 无 |

按表格调用 `query_scenario(scene_name=...)`：

1. 先查询第一次查询名。
2. 如果返回 `success=true` 且 `data` 非空，立即使用该结果，不再扩大查询。
3. 只有返回 `success=true` 且 `data` 为空，或返回 `SCENE_NOT_FOUND` 时，才查询第二次查询名。
4. 如果没有第二次查询名，则不重试。
5. 其他失败表示查询异常，说明工具返回的原因并结束；不要扩大查询，也不要将失败当成空列表。

```text
# 「打开地月航班运输场景」
query_scenario(scene_name="地月航班运输场景")
# 仅空结果时
query_scenario(scene_name="地月航班运输")

# 「打开10001场景」
query_scenario(scene_name="10001场景")
# 仅空结果时
query_scenario(scene_name="10001")

# 「打开场景502」
query_scenario(scene_name="场景502")
# 仅空结果时
query_scenario(scene_name="502")
```

不要为了匹配指定名称而调用 `query_scenario()` 查询全部场景。只有未明确划定完整名称的
`xxx场景` / `场景xxx` 表达才允许在空结果后执行第二次基础名称查询。

## 2. 检查最终查询结果

从最后一次有效 `query_scenario` 的 ToolMessage `data` 读取规范化场景列表。
如果第一次查询已经返回非空结果，它就是最终结果。

### 将 `scene_name` 当作不透明标识符

查询结果中的 `scene_name` 不是需要润色或分词的自然语言，而是后续打开场景所需的不透明标识符。
从工具结果逐字符复制它，展示候选和调用 `open_scenario` 时都必须保持完全一致：

- 保留原有空格，也保留原本没有空格的位置。
- 不得在中文、数字、拉丁字母之间添加空格。
- 不得改动大小写、下划线、连字符、标点或任何其他字符。
- 不得根据用户输入、场景含义或排版习惯重建名称。

例如，工具返回以下名称时，只能原样使用左侧值，右侧写法是错误的：

| 工具返回的 `scene_name`（正确） | 禁止改写为 |
| --- | --- |
| `场景0942_ 1个火箭_1个卫星关节动画` | `场景 0942_ 1 个火箭_1 个卫星关节动画` |
| `A地球-CZ4C火箭Demon` | `A 地球-CZ4C 火箭 Demon` |

## 3. 按匹配数量分流

- `0` 条：告知用户未找到对应场景，结束。最终查询返回 `SCENE_NOT_FOUND` 同样表示场景不存在。
- `1` 条：使用该条结果中原始、完整的 `scene_name` 调用 `open_scenario`。
- 多条：**必须**返回 `status=info`、`code=MISSING_REQUIRED_INFO`，让工作流进入等待用户状态；
  `summary` 使用下面的固定候选格式，`data` 携带查询结果数组。不要自行选择或打开。

不要把工具的原始 JSON 直接展示给用户。

用户指定了查询名称时，使用实际生效的查询名：

```text
查询成功，找到 {n} 个包含“{query_name}”的场景
```

用户没有指定名称时，首句改为：

```text
查询成功，找到 {n} 个场景：
```

其中 `{n}` 必须使用实际候选数量，`{query_name}` 必须使用产生最终结果的那次查询参数。
表格每行对应一个候选，不要遗漏，不要让模型根据文字描述猜测数量。

多条候选时 `WorkerResponse.data` 的固定结构（`data` 中每个对象含
`scene_name`、`update_time`、`uploader_name` 字段，值逐字符来自查询结果）：

```json
{
  "data": [
    {"scene_name": "场景0942_ 1个火箭_1个卫星关节动画", "update_time": "2024-11-22", "uploader_name": "-"}
  ]
}
```

用户回答序号或场景名后（任务文本会带「用户补充」与「补充数据」），按本技能流程
用补充数据中对应的真实 `scene_name` 重新执行打开，不需要再次查询。

## 4. 打开唯一场景

首次调用不要传保存决策：

```text
open_scenario(scene_name="<唯一匹配结果的真实场景名>")
```

按工具结果回复：

| 结果 | 处理 |
|------|------|
| `success=true` 或 `SCENE_OPENED` | 告知用户已打开该场景。 |
| `SCENE_NOT_FOUND` | 告知用户该场景不存在或可能已被删除。 |
| `SCENE_UNSAVED_CHANGES` | 工具会中断并要求用户选择是否保存；恢复后工具按用户的 `yes/no` 决策继续打开。Worker 不得替用户选择或自行重试。 |
| 其他失败 | 说明打开失败及工具返回的原因；不要重复调用。 |

## 必须遵守

- 未指定场景名称时才查询全部场景。
- 引号或「叫/名为」等表达明确指定完整名称时，只查询该名称一次，不扩大查询。
- 未明确划定完整名称时，先查询包含「场景」的名称；仅空结果时查询去掉边界「场景」后的基础名称。
- 第一次查询已有结果时不得扩大查询，指定名称时不得查询全部场景。
- 只有匹配结果唯一时才打开。
- `open_scenario` 不接受保存决策参数；未保存变更必须由工具中断后取得用户决定。
- 使用查询结果中的真实 `scene_name`，不要使用用户输入拼接出的名称调用打开工具。
- 匹配多条时返回 `status=info`、`code=MISSING_REQUIRED_INFO` 并在 `data`
  携带完整候选，等待用户指定；匹配不到或收到 `SCENE_NOT_FOUND` 时明确告知不存在。
- 用户补充序号或名称后，直接使用补充数据中的真实 `scene_name` 打开，不再查询。
- `scene_name` 是不透明标识符；展示和传参时逐字符复制，禁止增删空格或改动任何字符。
